> 前置阅读：[阶段四：求职](stage-04-job-hunting.md)（本阶段是阶段四"技术面试题库"的知识底座补强）。

## 一、这个阶段在学什么

前三个阶段回答了"agent 怎么用模型"，本阶段回答两个面试官一定会追问、而纯应用开发者答不上来的问题：

1. **模型侧理解**：这个每天被你调 API 的东西到底是怎么来的——Transformer 在算什么、tokenizer 为什么让模型数错"strawberry 有几个 r"、pretrain/SFT/RLHF 三阶段各自赋予了什么能力、推理模型（R1/o1 类）与普通模型的本质差异。
2. **微调决策**：什么时候该微调、什么时候该 RAG、什么时候两个都不该做——这是"会用 API"和"会做技术选型"的分水岭，也是 JD 里"熟悉 LoRA 微调优先"的实际考点。

**学习目标**：不是会训练模型（应用岗不要求），而是概念级理解精确到"面试追问三层不卡壳"，并且每个概念都能串联到 mini-agent / kb-agent / 多智能体系统的真实设计上。

## 二、核心概念（必须能脱稿讲出来）

### 1. Transformer 与 attention：信息是怎么在模型里流动的

直觉版（够用且准确）：文本被切成 token → 每个 token 变成一个向量 → 经过 N 层"互相看"：每个 token 的向量都会根据**相关性**吸收其他 token 向量的信息（这就是 self-attention——"它"指代谁、数字和单位的关系，全靠这一步建立）→ 最后一层输出"下一个 token 的概率分布"。

要记住的三个推论（面试真正考的）：

- **为什么取代 RNN**：attention 对任意距离的两个 token 一视同仁（长距离依赖不再衰减），且训练时可全序列并行（工程上能吃满 GPU）——这两条决定了大模型时代的规模可行性；
- **为什么上下文窗口是硬上限**：attention 的计算量随序列长度平方增长（这是第 1 章"成本 O(n²)"和第 3 章"压缩"的物理根源）；
- **为什么模型"一本正经地胡说"**：生成 = 逐 token 采样概率分布，模型没有"知道/不知道"的内部开关——它只是在续写最可能的文本。这是幻觉的**机制级**解释，比"训练数据有误"这类说法深一层，也是 RAG 防幻觉设计的动机。

### 2. Tokenizer：模型眼里没有"字"，只有子词

BPE（字节对编码）按统计频率把文本切成**子词**单元：常见词一个 token，生僻字拆成碎片，数字经常被拆成单个数位。直接可观察的后果：

- "strawberry 有几个 r"数错——模型看到的不是字母而是子词块，字母级信息根本不在输入里；
- **算术不可靠**——`357×482` 的数字被拆碎、乘法又是多步精确运算，纯概率续写必错。**这就是 mini-agent 第 1 条规则"算术必须用 calculator 工具"的模型层根因**（串联点：tokenizer 原理 → 工具设计）；
- 中英文 token 成本不同：同一语义英文通常更省 token；prompt 里的缩进、换行、Markdown 符号全都计费。

实操动作：拿 DeepSeek/OpenAI 的 tokenizer 工具，把自己项目的 system prompt 贴进去看切分结果——看过一次就再也忘不掉。

### 3. 训练三阶段：base → instruct → aligned

| 阶段 | 数据 | 目标 | 能力变化 |
| --- | --- | --- | --- |
| **Pretrain（预训练）** | 全网文本（万亿 token 级） | 预测下一个 token | 知识 + 语言能力；产出 base model——只会**续写**，不会"回答" |
| **SFT（监督微调）** | 人工编写的指令-回答对（万~百万级） | 模仿标准回答 | 学会"回答问题而不是续写文本"；输出格式、风格在此定型 |
| **RLHF / DPO（偏好对齐）** | 人类对多个回答的排序/偏好 | 最大化人类偏好得分 | 有用性、无害性；**拒答行为就来自这里** |

三个常考深挖：

- RLHF 的经典实现是 PPO + reward model（用人类排序训练一个"打分模型"，再用它做 RL 的奖励信号）；DPO 是更简单的直接偏好优化（不需要单独的 reward model 和 RL 循环）——知道"RLHF 不是监督学习，是强化学习"这个分界即可；
- **每个阶段能修什么问题**：知识错了靠预训练（你碰不到）；格式/语气不对靠 SFT；拒答过激/太啰嗦靠对齐——这个对应关系就是微调决策的理论基础；
- 能力来源的争议共识：预训练注入绝大部分能力，SFT/RLHF 更多是"唤醒和约束"（所以小数据也能 SFT 出可用模型）。

### 4. 推理模型（reasoning）：RL 训出来的"先想后答"

o1 / DeepSeek-R1 这类模型与普通 chat 模型的本质差异：用强化学习训练模型产出**长思维链**（CoT）再回答——思考过程是模型自己生成的，不需要你在 prompt 里写"let's think step by step"。

应用侧必须知道的四点：

- **什么时候用**：复杂规划、数学/代码、多步推理——agent 的 planner 角色是天然场景（串联阶段三：planner 用推理模型、worker 用便宜模型，这就是"模型分级"的又一个理由）；
- **什么时候别用**：简单问答、闲聊、低延迟场景——推理模型的思考 token 也计费，延迟显著更高；
- **prompt 写法不同**：不要再塞手写 CoT 提示，问题描述清楚即可；
- DeepSeek-R1 的知识点：以 RL 为主训练出推理能力，并通过蒸馏把小模型也带上推理能力（"蒸馏"= 用大模型的输出当训练数据教小模型）。

### 5. LoRA / QLoRA：微调为什么在单卡上也可行

- **全参微调**的问题：7B 模型训练要几百 GB 显存，且容易"学新忘旧"（灾难性遗忘）；
- **LoRA**：冻结主干权重，只在 attention 层旁边插一对**低秩矩阵**（A×B，秩 r 通常 8-64）——可训练参数降到 1% 以下，效果接近全参微调。直觉：模型行为的"差量"是低维的，不需要动全部参数；
- **QLoRA** = 4-bit 量化的底模 + LoRA：显存再降一个量级，消费级显卡可玩；
- 应用岗要会的一句话："LoRA 让我能用 SFT 的价格定制模型的行为和格式，而不是重新训练一个模型。"

### 6. RAG vs 微调：决策框架（本阶段的题眼）

**微调改的是"行为"，RAG 补的是"知识"**——这是第一性原理，其余都是推论：

| 需求 | 该用什么 | 为什么 |
| --- | --- | --- |
| 知识要新鲜、可追溯、带引用 | RAG | 知识在库里，改库即改答案；微调把知识"焊死"在权重里，更新要重训 |
| 输出格式顽固地错（如总要它输出特定 JSON 方言） | 微调（SFT） | 格式是行为，prompt 说不听就用数据教 |
| 领域黑话/语气/角色人设 | 微调优先，prompt 先试 | 风格类需求小数据 SFT 就有效 |
| 私有知识问答 | RAG，**不要微调** | 微调注入知识不可靠（会"装知道"地幻觉），且无法溯源 |
| 都不行时 | 先检查 prompt | 90% 的"要微调"其实是 prompt 没写到位 |

决策顺序（和阶段三"先 prompt 再工具再 workflow 最后 multi-agent"同一种保守主义）：**prompt → RAG → 微调**，每一步都先证明上一步不够。

## 三、知识梳理（复习资料）

### 3.1 自问自答考点清单

<details><summary>Q：为什么 LLM 心算大数乘法必错？</summary>两层原因：tokenizer 把数字拆碎（357 可能是 "35"+"7"），且逐 token 概率生成不适合多步精确运算。这正是 agent 要给模型配 calculator 工具的原因——用工具补模型的结构性短板。</details>

<details><summary>Q：base model 和 chat model 有什么区别？</summary>同一个预训练底模；chat model = base + SFT（学会按指令回答）+ 偏好对齐（有用无害、会拒答）。base model 拿到"1+1="会续写算术题，chat model 会回答"2"。</details>

<details><summary>Q：RLHF 是监督学习吗？</summary>不是。它是强化学习（PPO）：奖励信号来自单独训练的 reward model。SFT 才是监督学习。DPO 是两者的折中——用偏好对直接做类似监督的优化，省掉 reward model 和 RL 循环。</details>

<details><summary>Q：幻觉能不能被"修好"？</summary>不能根除，只能抑制。机制上模型没有"自知无知"的开关（逐 token 采样）。工程上靠：RAG 给资料 + 防幻觉 prompt 给退路 + 引用标注可核查（=你的项目 2 三件套）。这也是"为什么 RAG 是应用层的标准答案"。</details>

<details><summary>Q：推理模型为什么更适合当 planner？</summary>规划是多步推理任务，推理模型的长思维链直接提升拆解质量；代价是延迟和成本，所以只给 planner 用、worker 用普通模型——模型分级。</details>

<details><summary>Q：微调能把公司知识库"训进去"吗？</summary>不该这么做。权重里的知识不可溯源、更新需重训、且模型会对没训过的内容"装作知道"。知识归 RAG，行为归微调。</details>

<details><summary>Q：LoRA 的"秩"是什么？为什么低秩就够？</summary>秩 = 旁路矩阵的中间维度 r。模型行为调整所需的"差量"在经验上是低维的，所以 r=8~64 的小矩阵就能拟合，参数省 99%。</details>

<details><summary>Q：长上下文模型（百万 token）出来后 RAG 还有意义吗？</summary>有。三点：① 成本——全量塞入每次调用都计费，检索只取 top-k；② 效果——"lost in the middle"，长上下文中间段信息利用率显著下降；③ 可溯源/权限控制。长上下文和 RAG 是互补不是替代。</details>

<details><summary>Q：temperature 到底在调什么？（复习串联）</summary>采样分布的平滑度：0 = 总选概率最高的 token（确定性），>1 更随机。工具调用/JSON 输出场景调低，创意场景调高。本质是控制"概率续写"的离散程度。</details>

<details><summary>Q：prompt caching 和微调都能"复用前缀"，是一回事吗？</summary>不是。缓存复用的是**推理**（省重复前缀的计算费），模型行为不变；微调改变的是权重本身。缓存省成本，微调改行为。</details>

### 3.2 易混淆概念对比表

| 对比 | 一句话区分 |
| --- | --- |
| base vs instruct vs reasoning | 会续写 → 会回答 → 会先想再答 |
| SFT vs RLHF vs DPO | 模仿标准答案 → RL 优化人类偏好 → 免 RL 的偏好优化 |
| LoRA vs QLoRA vs 全参微调 | 低秩旁路 → 4bit 底模+旁路 → 全量权重都动（应用岗基本用不上） |
| RAG vs 微调 vs 长上下文直塞 | 知识外置可追溯 → 行为内置 → 临时全量（贵且中间会丢） |
| 蒸馏 vs 量化 | 大模型教小模型（能力迁移）→ 权重降精度（体积压缩），常被一起提到但互不相干 |

### 3.3 决策流程图

```
需求来了
  │
  ├─ 模型"不会答"（缺知识）？
  │     ├─ 是 → 知识要新鲜/可溯源？ ── 是 → RAG
  │     │                            └─ 否（极少见）→ 评估微调
  │     └─ 否 ↓
  ├─ 模型"答不好"（格式/风格/语气）？
  │     ├─ prompt 能修？── 能 → 改 prompt（收工）
  │     └─ 顽固 → SFT（LoRA，小数据先试）
  └─ 模型"想不深"（规划/推理差）？
        └─ 换推理模型当 planner，别先想微调
```

## 四、注意事项（易踩坑）

1. **吹牛边界**：没跑过训练就自称"概念级理解，没实操"——面试官追问 loss 曲线时编不下去，反而扣分。诚实边界 + 决策能力 > 虚假实操。
2. **"微调注入知识"是面试陷阱题**：主动说"不该这么做"并给出 RAG 替代方案，是加分回答；掉进"可以啊然后评估效果"就暴露了。
3. **术语精度**：RLHF ≠ 监督学习；蒸馏 ≠ 量化；LoRA 不是"小模型"。术语说错比不知道更糟。
4. **别把推理模型当万能**：被问"为什么不全用 R1"，要答得出延迟、成本、简单任务无收益三条。
5. **时效事实要标注**：模型窗口、价格、榜单排名都在快速变化，面试时说"我了解的截至 XX 时间是……，以官方为准"是成熟的表现。
6. **学这块别陷入数学**：应用岗不要求手推 attention 公式；能讲清"信息怎么流动、为什么平方复杂度"就够，省下的时间去练系统设计题。
